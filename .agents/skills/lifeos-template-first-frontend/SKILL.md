# LifeOS Template-First Frontend

This is a product-specific skill for `A-J-AXE/liferpg`, not a license to generate a web marketing page.

1. Read `docs/rebuild/REBUILD-DECISIONS.md`, `component-source-map.md`, `asset-manifest.md`, `visual-reference-matrix.md` and `reward-v3.1-contract.md`. Read `AGENTS.md`.
2. Search **actual pinned GitHub source files**, not screenshot summaries. Reuse a compatible source component or a genuine original asset. Log exact source SHA, path, legal notice and local path. If absent, report rather than fabricate it.
3. Determine the **single task flow** (sidebar, task edit, calendar, RPG home, habits, skills or workout). Choose the matching **different** content layout; avoid generic cards repeated in every surface.
4. Apply UI UX Pro Max for typography/tokens, Frontend UI Engineering/shadcn for accessible React engineering, explicit Minimalist UI for Planner density, optional Taste Skill for RPG screenshot critique. All external skill rules yield to v3.1 reward contract and LifeOS workflows.
5. Use local `DEMO / NOT EARNED` fixtures only for frontend phases PR 01–06. No pretend wallet payouts or task-completion receipts.
6. Run actual Chrome/Edge via Playwright, compare with reference screenshots at 1440/1280/1024/390 widths in both modes; test Tab/Enter/Escape, drag, focus, dialogs and responsive overflow.
7. Fix actual screenshot/interaction regressions, do not mark solved by TypeScript alone.
8. Commit one micro-PR with tests, asset/source manifest updates, screenshots, remaining failures and reviewer gate. Stop at the current PR, do not race to the reward backend.

## Forbidden

Do not invent 3D artwork or custom ornamental SVGs; do not claim 3Dicons website files are an individual asset pack; do not clone admin statistic dashboards; do not apply Taste Skill's marketing hero spacing to dense Planner or OpenGym; do not copy OpenGym's separately licensed exercise images; do not merge/rewrite other branches or deploy publicly.
