# UI acceptance checklist

Apply to each changed interaction before calling it ready for review.

- [ ] The primary action is apparent at the normal desktop width and on a narrow screen.
- [ ] A common action can be finished in place without a general form.
- [ ] Advanced properties appear only after an explicit request.
- [ ] Icons have accessible names and discoverable explanations. Touch does not depend on hover.
- [ ] Controls fit without hiding a necessary value, action or validation message.
- [ ] Compare the composition to both owner-provided images in UI_REFERENCE.md.
- [ ] Reuse installed shadcn primitives, shared tokens and project imagery.
- [ ] Exercise Tab, Enter and Escape, including nested picker dismissal and focus return.
- [ ] Verify persisted behavior, recurrence, files, completion and reward paths as applicable. For timers exercise pause, link, expand, navigate, reload and reset.
- [ ] Inspect rendered Light, Black and narrow versions. Record observed differences and unresolved items.
